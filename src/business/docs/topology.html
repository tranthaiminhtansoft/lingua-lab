Routes and composition

src/app/main.tsx mounts a RouterProvider using the createBrowserRouter in src/app/router.tsx. The home route is /; the Nihongo hub is /nihongo-o-benkyuo, with Kana, Grammar, Vocabulary, and first-introductions lesson routes beneath it. The legacy /lessons/kana address redirects to the nested Kana route. Unmatched routes show a not-found view inside the shell.

AppShell provides shared branding and lesson navigation. Lesson metadata is centralized in nihongo/lessonRegistry.ts; hub and navigation read that registry. Current entries are available, while the UI also supports a coming-soon status. Kana pronunciation calls the browser's speechSynthesis API; available voices and playback depend on the visitor's device.

Runtime boundaries

  • GitHub Pages serves static HTML, CSS, JavaScript, and bundled lesson data/assets.
  • React and route selection execute in the visitor's browser; no application backend or app-owned API is configured in the inspected app.
  • Build and deployment jobs belong to the control plane, not the runtime.
  • Vite uses / locally and /lingua-lab/ when GITHUB_ACTIONS is set. React Router uses Vite's base URL as its basename.

The configured public/404.html fallback restores deep paths under the project base. The repository E2E harness models that behavior; live Pages behavior is not established by this source inspection.
