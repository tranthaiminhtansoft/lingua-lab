Pre-release

Start hereProduct GuidelineReferenceProcedures

Check readiness before starting a release. This guide does not approve or deploy production.

  1. Open the current live site: Lingua Lab on GitHub Pages. Check the home page and a lesson route; note any visible issue for the release owner.
  2. Confirm the intended change is reviewed and merged to master. Record the expected commit and check the merged diff.
  3. Review applicable checks on the actual commit. CI is path-filtered; if no run exists, record that rather than treating it as passed. Run local checks when appropriate and record their results.
  4. Confirm the planned date is available. For subsequent releases, confirm an existing published stable release can serve as a rollback target. For the first release, explicitly record rollback unavailable, obtain release-owner acceptance of that risk, and write a manual recovery plan before the production approval.
